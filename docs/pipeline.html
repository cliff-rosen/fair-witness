Fair Witness — the pipeline, re-thought

A proposed target architecture for discussion (not the current code). Draft.

The one idea: extract the article's argument once, then judge it on two independent axes — Ring 0 · does it cohere? (internal: logic, consistency, rhetoric — judged on the article's own terms) and Ring 1 · does it correspond? (external: is it true, what's missing — judged against reality). The split matters because Ring 0 needs only the text and we can do it confidently; Ring 1 needs the world and is where grounding is required.

Stage 2 · sharedExtract the argument text-only ✓
Parse what the piece is arguing — not whether it's true. Classify genre, name the topic, and build the argument structure: the thesis and the claims that hold it up. This is the substrate both rings operate on.
inExtractedArticle
outArgumentMap  (upgrade: today this is a flat claim list)
ArgumentMap { genre, topic, main_subject, summary, thesis, // the central point being argued claims[]: { id, text, kind, // fact | statistic | causal | prediction | opinion | value as_presented, // asserted | attributed | hedged supports[], // which claim/thesis ids this backs → the structure load_bearing // 0–100: how central to the thesis } }
full schema / why this changes
The key upgrade is supports[] + load_bearing: instead of a flat list of claims, we capture how the claims connect into an argument. That graph is exactly what the two rings need — Ring 0 tests whether it holds together; Ring 1 tests whether its load-bearing pieces are true. The set of high-load_bearing claims = the "argument spine."
fan out — both rings run off the ArgumentMap
Ring 0 · Internal — “does it cohere?” judged on the article's own terms · needs only the text ✓
A · Logic & argument
Does the thesis actually follow from the claims? Gaps, leaps, contradictions, circularity — does it close the loop A→Z?
CoherenceAssessment { score, follows_from_premises, gaps[], contradictions[], unsupported_leaps[], closes_loop, rationale }
★ mostly missing today
B · Rhetoric & style
Loaded/emotive language, tone bleeding into reporting, editorializing — the manner, with verbatim quotes.
RhetoricAssessment { score, loaded_language[]{quote,why}, tone, editorializing[], rationale }
✓ ~ today's loaded_language / tone dimensions
C · Structural self-consistency
Does the headline/lede match the body? Are the piece's own claims attributed or just asserted? Is opinion separated from fact within itself?
StructuralAssessment { score, headline_matches_body, attribution_within_text, opinion_fact_separation, evidence[] }
✓ ~ today's headline / attribution dimensions
Ring 1 · External — “does it correspond?” judged against reality · needs the world ⚠
↳ Seeded by the argument spine from Ring 0: we only reality-check the load-bearing claims, not every sentence. This is why internal precedes external.
Reality model (the "issue map")
An independent map of the debate: sides, settled facts, common biases. Today: model memory. Proposed: retrieval-grounded with sources.
RealityModel { structure, sides[], settled_facts[], common_biases[], sources[] }
⚠ the least-grounded thing we show today
Claim check (per load-bearing claim)
Does each spine claim match / contradict / lack support against the reality model? Is it handled fairly or overstated?
ClaimCheck[] { claim_id, verdict: supported|contradicted|unsupported|unverifiable, handling, sources[] }
Omission & framing
What relevant perspectives/facts are absent vs. what exists? Whose framing did it adopt? Both-sidesing vs. false-consensus.
OmissionAssessment { missing_perspectives[], missing_facts[], adopted_framing, both_sidesing, false_consensus, severity }
Stage 4 · sharedSynthesize → two-axis verdict
Blend each ring into its own score. Keep them separate so a piece can be "tight reasoning, shaky facts" or vice-versa — and so the reader can see which axis is trustworthy.
inArgumentMap + Ring 0 facets + Ring 1 facets
outVerdict
Verdict { coherence_score, // Ring 0 — high confidence, text-grounded correspondence_score, // Ring 1 — depends on the reality model overall_score, fairness_label, political_lean, flags: { both_sidesing, false_consensus }, executive_summary, key_strengths[], key_concerns[] }
OutputBiasReport
All slots assembled, streamed to the UI stage-by-stage. The report shows the two axes side by side, with Ring 0 findings and Ring 1 findings visibly separated.
BiasReport { article, argument_map, ring0{coherence, rhetoric, structural}, ring1{reality_model, claim_checks[], omission}, verdict }
